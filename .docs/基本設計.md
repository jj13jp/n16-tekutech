# 基本設計

## 1. システム構成

ブラウザからのリクエストを Next.js（App Router / ISR）が受け取り、microCMS API からコンテンツを取得してレンダリングする 2 層構成。

- **フロントエンド層:** Next.js。Server Components でデータ取得とレンダリングを行い、静的ページとして配信する。検索フォームのみ Client Component とする
- **コンテンツ層:** microCMS。記事・カテゴリ・タグを管理する。API キーはサーバーサイド専用の環境変数で管理し、ブラウザには露出しない

## 2. 画面一覧

| 画面名 | URL | 概要 |
|--------|-----|------|
| 記事一覧（トップ） | `/` | 全記事を新着順で表示。ページネーション付き |
| 記事詳細 | `/articles/[id]` | 記事の全文・メタ情報を表示 |
| カテゴリ別記事一覧 | `/categories/[id]` | カテゴリでフィルタした記事一覧 |
| タグ別記事一覧 | `/tags/[id]` | タグでフィルタした記事一覧 |
| 検索結果 | `/search?q=xxx` | キーワードで絞り込んだ記事一覧 |

## 3. 画面遷移

- トップから記事カードをクリック → 記事詳細へ
- 記事カードのカテゴリラベルをクリック → カテゴリ別一覧へ
- 記事カードのタグをクリック → タグ別一覧へ
- ヘッダー（またはトップ）の検索フォームを送信 → 検索結果へ
- 記事詳細の「記事一覧に戻る」リンク → トップへ

## 4. コンポーネント設計

### レイアウト

`RootLayout`（layout.tsx）がすべてのページを包む。共通メタデータ（タイトルテンプレート・OGP）をここで定義する。

### 共通コンポーネント

| コンポーネント | 種別 | 役割 |
|--------------|------|------|
| `ArticleCard` | Server | 記事の概要カード（タイトル・サムネイル・カテゴリ・タグ・日付） |
| `Pagination` | Server | ページ番号リンクの一覧 |
| `SearchForm` | Client | 検索キーワード入力・送信フォーム |

### ページコンポーネント

| ページ | 種別 | 主な役割 |
|--------|------|---------|
| `app/page.tsx` | Server | 記事一覧取得・表示 |
| `app/articles/[id]/page.tsx` | Server | 記事詳細取得・表示・OGP 生成 |
| `app/categories/[id]/page.tsx` | Server | カテゴリ別記事取得・表示 |
| `app/tags/[id]/page.tsx` | Server | タグ別記事取得・表示 |
| `app/search/page.tsx` | Server | 検索結果取得・表示 |

## 5. データモデル

### microCMS スキーマ

**articles（記事）**

| フィールド ID | フィールド名 | 型 | 必須 |
|-------------|-----------|-----|------|
| title | タイトル | テキスト | ✔ |
| body | 本文 | リッチエディタ | ✔ |
| summary | サマリー | テキストエリア | |
| coverImage | カバー画像 | 画像 | |
| category | カテゴリ | コンテンツ参照（categories） | ✔ |
| tags | タグ | 複数コンテンツ参照（tags） | |

**categories（カテゴリ）**

| フィールド ID | フィールド名 | 型 | 必須 |
|-------------|-----------|-----|------|
| name | カテゴリ名 | テキスト | ✔ |

**tags（タグ）**

| フィールド ID | フィールド名 | 型 | 必須 |
|-------------|-----------|-----|------|
| name | タグ名 | テキスト | ✔ |

> microCMS のコンテンツ ID（`id` フィールド）を URL のキーとして使用する。`slug` フィールドは設けない。

### アプリ内型定義（概略）

```typescript
type Category = MicroCMSListContent & { name: string }
type Tag      = MicroCMSListContent & { name: string }
type Article  = MicroCMSListContent & {
  title: string
  body: string
  summary?: string
  coverImage?: MicroCMSImage
  category: Category
  tags: Tag[]
}
```

## 6. 技術スタック

| 領域 | 採用技術 | 理由 |
|------|---------|------|
| フレームワーク | Next.js 16（App Router） | ISR・SEO 対応、プロジェクト既存 |
| 言語 | TypeScript | 型安全 |
| スタイリング | Tailwind CSS v4 | プロジェクト既存 |
| ヘッドレス CMS | microCMS | 日本語サポート、SDK 充実 |
| HTML サニタイズ | sanitize-html | リッチエディタ出力の XSS 対策 |
| Linter / Formatter | Biome | プロジェクト既存 |
| デプロイ | 未定（Vercel 推奨） | Next.js との親和性 |

## 7. レンダリング方針

| 対象 | 方式 | revalidate |
|------|------|-----------|
| 記事一覧・詳細 | ISR | 60 秒 |
| カテゴリ・タグ一覧 | ISR | 3600 秒（1 時間） |
| 検索結果 | Dynamic（リクエスト時） | なし |

## 8. 非機能要件

| 項目 | 方針 |
|------|------|
| セキュリティ | リッチエディタ出力は sanitize-html でサニタイズ。API キーはサーバーサイド専用環境変数で管理 |
| アクセシビリティ | セマンティック HTML（`article`・`nav`・`time` 等）、画像に alt テキスト |
| レスポンシブ | Tailwind のブレークポイントでモバイル・PC 対応 |
| OGP / SEO | layout.tsx で共通テンプレート、各ページで `generateMetadata` を使い個別設定 |
